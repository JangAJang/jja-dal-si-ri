# 런북: 앱 버전 릴리스

목적: 앱에 쌓인 변경을 새 버전으로 확정하고, 패치노트·루트 목록·태그를 맞춘다.

## 수정할 파일 (순서대로)
0. 릴리스 이슈와 브랜치를 만든다 (`docs/runbooks/작업-브랜치-PR.md`): `leejanghee/release/<앱이름>/<이슈번호>/vx-y-z`
1. `apps/<앱이름>/CHANGELOG.md` — `[Unreleased]` 내용을 보고 올릴 자리를 정한다.
   - 사용법/데이터 호환이 깨짐 → MAJOR, 기능 추가 → MINOR, 버그 수정·손질 → PATCH
   - `0.x` 동안은 호환이 깨지는 변경도 MINOR로 올려도 된다.
2. 같은 파일 — `[Unreleased]` 아래 항목들을 새 섹션 `## [x.y.z] - YYYY-MM-DD`로 옮기고, 빈 `## [Unreleased]`를 맨 위에 다시 둔다.
   항목은 `Added`/`Changed`/`Fixed` 등으로 분류하고, 사람이 읽을 수 있는 한 줄로 쓴다.
3. 앱 매니페스트 버전 필드 — `build.gradle`(`version`) / `package.json`(`version`) / `pyproject.toml`(`version`) 중 그 앱에 있는 것 전부.
4. `README.md`(루트) — 앱 목록 표의 **현재 버전** 칸을 고친다. `1.0.0`에 도달하면 **상태**를 `사용중`으로 바꾼다.

## 실행
```bash
git add apps/<앱이름> README.md
git commit -m "release(<앱이름>): vx.y.z (#<이슈번호>)"
git push -u origin HEAD
gh pr create --base main --title "release(<앱이름>): vx.y.z (#<이슈번호>)" --body "Closes #<이슈번호>"

# PR 머지 후 main에서 태그
git switch main && git pull
git tag <앱이름>/vx.y.z
git push origin <앱이름>/vx.y.z
```

## 검증
- `CHANGELOG.md` 최신 버전 섹션 = 매니페스트 버전 = 루트 `README.md` 표 버전, 세 값이 같다.
- `git tag -l "<앱이름>/*"`에 새 태그가 있다.
- `cd apps/<앱이름> && docker compose up --build`가 여전히 뜬다.

## 흔한 함정
- 루트 `README.md` 표를 빼먹기 쉽다 — 릴리스 커밋 하나에 세 파일이 모두 들어가야 한다.
- 다른 앱의 변경을 같은 릴리스 커밋에 섞지 않는다.
- 태그를 릴리스 브랜치에서 붙이면 squash 머지 후 `main`에 없는 커밋을 가리키게 된다 — 반드시 머지 후 `main`에서 붙인다.
- `[Unreleased]`가 비어 있으면 릴리스할 변경이 없는 것이다. 먼저 변경 내역을 적는다.
