# 런북: 새 앱 추가

목적: `apps/` 아래에 독립 앱 하나를 새로 만들고 레포 목록에 등록한다.

## 수정할 파일 (순서대로)
0. 이슈와 브랜치를 만든다 (`docs/runbooks/작업-브랜치-PR.md`): `leejanghee/feat/<앱이름>/<이슈번호>/init-app`
1. `apps/<앱이름>/` — 빈 폴더를 만든다. 이름은 영문 소문자 kebab-case.
2. `apps/<앱이름>/` 안에서 `create-claude-app` 스킬을 실행한다 — 뼈대·컨테이너·앱 문서(README/CLAUDE/ARCHITECTURE/런북)가 생성된다.
   이 레포 규칙("앱끼리 코드 공유 금지")을 5번 질문(제약)의 답으로 전달한다.
3. `apps/<앱이름>/docker-compose.yaml` — 노출 포트를 배정 포트로 바꾼다 (`ARCHITECTURE.md > 포트 배정`: 이미 배정된 가장 큰 포트 + 10, 첫 앱은 `3010`).
   `ports:`의 **호스트 쪽만** 바꾼다 (예: `"3010:80"`). 컨테이너 쪽 포트는 그대로 둔다.
4. `apps/<앱이름>/README.md`·`CLAUDE.md` — 생성된 문서 안의 `localhost:<프리셋 기본 포트>`를 배정 포트로 고친다.
5. `apps/<앱이름>/CHANGELOG.md` — `docs/templates/app/CHANGELOG.md`를 복사해 앱이름·프리셋·날짜를 채운다.
6. 앱 매니페스트 버전 필드를 `0.1.0`으로 맞춘다 — `build.gradle`(`version`) / `package.json`(`version`) / `pyproject.toml`(`version`) 중 생성된 것 전부.
7. `README.md`(루트) — 앱 목록 표에 한 줄 추가: 앱 폴더 링크 · 설명 · `0.1.0` · `개발중` · `http://localhost:<배정 포트>`(포트 없으면 `-`) · CHANGELOG 링크. `_(아직 없음)_` 행이 있으면 지운다.

## 실행
```bash
cd apps/<앱이름>
docker compose up --build
```

## 검증
- `docker compose up` 후 배정 포트 주소에서 참조 구현 화면(또는 `/api/health`)이 뜬다.
- 루트 `README.md` 표의 버전 = `CHANGELOG.md` 최신 버전 = 매니페스트 버전 (`0.1.0`).
- 앱 폴더 안에 프리셋 기본 포트(`localhost:3000`/`localhost:8080`)가 문서·compose에 남아 있지 않다.
- 다른 앱 폴더나 루트 공용 폴더를 참조하는 코드가 없다.
- PR이 `main`에 머지된 뒤 `main`에서 태그: `git tag <앱이름>/v0.1.0 && git push origin <앱이름>/v0.1.0`

## 흔한 함정
- `create-claude-app`은 빈 디렉토리를 요구한다. `CHANGELOG.md`를 먼저 복사하면 스킬이 멈춘다 — 반드시 뼈대 생성 **후에** 복사한다.
- `create-claude-app`은 git 저장소를 새로 만들지 않아야 한다 — 앱 폴더 안에 `.git`이 생기면 지운다(이 레포 하나로 관리).
- 프리셋 기본 포트(3000/8080)를 그대로 두면 다른 앱과 동시에 띄울 때 충돌한다.
- 앱 안의 `.gitignore`·`.dockerignore`에 `.env`가 들어 있는지 확인한다.
